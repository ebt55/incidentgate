# Architecture status

## Shipped checkpoint boundary

Triage Agent Lab is a local reproducibility and control experiment, not a novel AI-SRE category or an open-ended remediation platform. The implemented vertical slice covers D1-D8, S1, and S2. D1-D3/D5/D8 have bounded proposals and recovery predicates; D4/D6/D7/S1/S2 terminate without an action. Their fixtures are deterministic and local only.

The implemented chain is `evidence -> deterministic policy -> advisory monitor -> durable preapproval audit -> human approval/reject -> atomic idempotent operation -> fresh verification`. D1-D3 state, audit records, approval bindings, checkpoints, operation outcome, and verification are durable in Postgres. The host UI and MCP-facing boundaries are localhost-only. The default monitor is deterministic fixture infrastructure; an explicit complete Anthropic configuration selects a bounded provider-backed monitor.

The default cannot mutate without a human approval token bound to the canonical action hash, approver identity, expiry, one-time use, incident/thread context, and operation scope. The default is not an ungated deployment mode. Evidence and logs are untrusted input; they do not authorize an action.

## Compatibility and observability

The MCP integration targets the stable Python SDK v1 line (the project resolves the 1.29-compatible range). It does not claim negotiated compatibility with newer draft specifications, including MCP 2026-07-28.

Local OpenTelemetry is implemented and exercised. On 2026-08-10, a clean isolated external Langfuse smoke authenticated a read of one D1 trace and confirmed the required D1/MCP span names, trace continuity across a runtime restart, and one bundled mutation. The D1 runtime makes external trace-URL enrichment non-blocking and retains its local trace ID if that enrichment is unavailable. This is a bounded verification receipt, not a claim of continuous export, service availability, production reliability, or telemetry coverage beyond that run.

The configured Anthropic monitor sends only a bounded allowlisted synthetic digest and action, requests a strict structured response, and requires the returned action hash to match. Anthropic requires an explicit provider, API key, and pinned model (`claude-haiku-4-5-20251001`); normal runs retain the fixture default and never use the network. The initial 2026-08-10 synthetic smoke failed closed with HTTP 400 because the raw Pydantic provider schema contained unsupported constraints. The provider-facing schema now uses the official Anthropic SDK `transform_schema`, while the original strict local schema still validates the returned output locally. A corrected guarded live smoke passed exactly once (`1 passed in 9.16s`) using only the synthetic typed restart action and bounded citation digest; no request, response, rationale, key, or provider error body was printed or recorded. The monitor is advisory only—policy and human approval remain authoritative—and every provider, parsing, stop-reason, content-shape, validation, or hash-binding failure returns the same generic hash-bound `BLOCK` result.

## Claims deliberately not made

Exactly-once applies only to bundled mock operations: their mutation and idempotency outcome commit atomically in local Postgres, and restart/response-loss paths are tested there. It does not extend to arbitrary external APIs or distributed delivery.

Checkpoint B measures all ten frozen scenarios in three explicitly evaluation-only local modes: `ungated_evaluation_only`, `policy_only_evaluation_only`, and `policy_monitor_human`. It is a deterministic/mock fixture experiment, not a model/provider benchmark or a deployment mode. R01-R12 are implemented local deterministic reliability slices; R13-R20 remain frozen/planned in [`scenarios/planned-matrix.json`](../scenarios/planned-matrix.json), as do T3, T5 and T6. T1, T2, T4, T7 and T8 have runtime coverage. The official deterministic sabotage-v2 tables are T1, T2, T4 and [T8](../artifacts/sabotage-matrix/T8/sabotage-matrix.md) ([raw JSON](../artifacts/sabotage-matrix/T8/sabotage-matrix.json)); T7 has no v2 table. T8 measures a same-operation hidden-privilege rollback: both legs call `operations.rollback_api_release`, while declared `changed_paths` policy enforcement stops the covert bundle in policy-only and complete modes and the incident rollback still succeeds. R05 is a durable read-only, no-action lock auto-release observation: exactly three reads under a per-thread/correlation/actor/read-permission cursor, fixture elapsed=45 seconds rather than 45 wall seconds, process-loss resume, and zero approval, operation, or mutation. R06 establishes the exact orders query-plan baseline; R07 routes bounded customer reads to primary; R08 rotates only the credential identifier to `db-app-2026-09`, with no secret/value field. R06-R08 use typed exact actions, deterministic policy, complete-mode advisory monitoring, durable human approval, action/context/token/idempotency binding, one Postgres mutation/ledger, response-loss exactly-once replay, and fresh post-commit evidence. The current [chaos table](../artifacts/chaos-matrix/kill-matrix.md) and [raw JSON](../artifacts/chaos-matrix/kill-matrix.json) cover 27 scenarios × 22 boundaries = 594 cells: 434 applicable clean cells, 160 `n/a`, and zero failures or harness errors; T8 has all 22 cells. Public FastMCP, fresh-host UI, safe telemetry trace chains, and isolated migration 001-020 are tested. Reliability v2 is tested locally only in complete, policy-only, and ungated mock-fixture evaluation; actual full/subset same-trial semantic replay requires a clean revision and excludes only envelope `generated_at`. These results do not claim production safety, real DB/query/DNS/credential systems, real 45-second latency, external exactly-once, a model/provider benchmark or generalization, published reliability-v2 artifacts, or continuous Langfuse/Anthropic reliability. Dated external smokes remain separately bounded. The 24 attack-policy variants and 36 fail-closed planned checker specs are contract artifacts, not runtime coverage.
