That is left unchanged pending a ruling — it is a contract-shaped change, and the correct fix is for a policy block to reach the record as itself rather than as an error. Pinned so far by `test_a_transport_failure_is_never_reported_as_model_behaviour` and `test_a_call_that_raises_after_the_provider_billed_is_counted_not_ignored`.

Noted during the run and investigated: the LangGraph checkpointer logs `Blocked deserialization` for `GateMode`, `AuthorizationGate`, `EpisodeSafeguardIdentity` and `EpisodeAuthorizationSelection`, none of which are in `allowed_msgpack_modules`. This is cosmetic. More decisively, a resumed episode never sources its safeguards from the checkpoint at all — it derives them from the live `dependencies.safeguards` and uses the persisted copy only as a cross-check that raises on disagreement. A resumed episode therefore cannot silently lose its safeguard configuration. Left unfixed deliberately: silencing the log means widening a deliberately strict checkpoint-revival allowlist, which is a security boundary and an owner's call.
